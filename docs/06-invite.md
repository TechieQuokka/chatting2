# 초대 시스템

## 모드별 초대 흐름 요약

| 모드 | 초대 방식 |
|------|----------|
| 인터넷 | 초대 코드 → DHT 등록/조회 → 연결 |
| 인트라넷 | mDNS 탐색 목록에서 직접 선택 → 연결 |
| 친구 초대 (공통) | 저장된 PeerId로 직접 연결 (모드 무관) |

## 새로운 사람 초대 (초대 코드, 인터넷 모드)

1. 방 멤버가 초대 코드 생성
2. DHT에 등록
   - DHT 등록 키: `hash(초대코드)` (원문 비노출)
   - 등록 값: `방 내부 ID + Ed25519 서명` (생성자 개인키로 서명)
   - 방 이름 레코드도 함께 갱신: `hash(방이름)` → `방 내부 ID` (피초대자가 방 이름으로 방을 탐색할 수 있게)
3. 카톡/이메일 등 외부 채널로 **방 이름 + 초대 코드** 전달
4. 상대방이 앱에서 방 이름 입력
   - DHT 조회 → `hash(방이름)` → 방 내부 ID 확인
   - 1개: 바로 초대 코드 입력 단계로
   - 복수(동명 방): 방 내부 ID 앞 8자리 목록 표시 → ↑↓ 이동 후 Enter로 선택
5. 초대 코드 입력 → hash(코드)로 DHT 조회 → 값 수신 → 생성자 공개키(PeerId 파생)로 서명 검증
   - 검증 성공 → 방 내부 ID 확인
   - 검증 실패 → 해당 응답 폐기, 다른 DHT 노드에서 재조회 (모두 실패 시 "연결 실패" 안내)
6. 온라인 멤버에게 연결 → 방 멤버가 입장 승인 → 방 키 전달 (Noise 암호화)
   - InviteRequest에 코드 생성자의 PeerId 포함 → 승인자가 생성자 식별 가능
7. 입장 완료 + 초대 코드 소멸
   - **친구 등록**: 승인자 + 피초대자 자동 등록
   - **코드 생성자 ≠ 승인자인 경우**: 코드 생성자의 피드에 `[알림] {피초대자 닉네임}이 입장했습니다` 표시 → 수동으로 `/add` 가능

## 초대 코드 보안

| 항목 | 내용 |
|------|------|
| TTL | 3분 (피초대자가 앱에 코드를 입력한 시점부터 카운트) |
| 시도 제한 | 코드 입력 오류 3회 시 차단 (brute-force 방어 목적) |
| 일회성 | 사용 즉시 소멸 |
| DHT 노출 | hash(코드)만 등록, 원문 비노출 |

- 방 멤버의 거절은 실패 카운트에 포함되지 않음 — TTL 내 재시도 가능
- 차단 기준은 잘못된 코드 입력 횟수만 카운트

## 방 이름 기반 DHT 탐색

- 방 이름은 DHT에 공개 등록 (방 존재 여부는 공개)
  - DHT 키: `hash("room_name_v1:" + 방이름)`
  - DHT 값: 방 내부 ID
- 등록 시점: 방 생성/입장 시, 초대 코드 생성 시 자동 갱신
- 동명 방이 복수 존재할 경우 방 내부 ID 앞 8자리 목록으로 구분
- 방 이름 형식 권장: `이름.접미사` (예: `test.dev1`, `dev.team`)

## 승인 화면

- 연결 요청 피어의 PeerId 핑거프린트 표시 (Ed25519 공개키 앞 16자리)
- 승인 권한: 방 멤버 누구나

### 다수 멤버 동시 처리 (선착순)

- 입장 요청 수신 시 현재 온라인인 모든 멤버에게 승인 팝업 표시
- 가장 먼저 응답한 멤버의 결정이 채택
- 승인 시 → 방 키 전달 시도 + 결정 결과 GossipSub 브로드캐스트 + 나머지 멤버의 팝업 자동 닫힘
- 거절 시 → 요청자에게 거절 통보 + 결정 결과 GossipSub 브로드캐스트 + 나머지 멤버의 팝업 자동 닫힘
- 거절된 경우 TTL 내 재시도 가능 (단, 3회 실패 시 차단)

#### 동시 승인으로 인한 방 키 중복 수신 처리

GossipSub 전파 지연으로 인해 두 멤버가 거의 동시에 승인 버튼을 눌러 피초대자가 InviteResponse(방 키 포함)를 2회 이상 수신할 수 있음:

- 피초대자는 방 키를 첫 번째로 수신한 즉시 해당 방 입장 완료 상태로 전환
- 이후 동일 방의 InviteResponse는 무시 (방 키는 고정값이므로 중복 수신 결과 동일)
- 별도 잠금 프로토콜 없이 수신 측 멱등성 처리만으로 충분

### 승인 후 방 키 전달 실패 시 폴백

- 승인자가 방 키 전달 후 10초 내 피초대자가 수신 확인 없을 시 → 전달 실패로 간주
- 피초대자가 다른 온라인 멤버에게 자동 재연결 시도
- 매 재연결 시도 전 TTL 잔여 시간 체크:
  - TTL 만료 → 폴백 즉시 중단, "초대 코드가 만료됐습니다. 새 초대 코드를 요청하세요." 안내
  - TTL 유효 → 재연결 시도 계속
- 재연결받은 멤버의 처리:
  - GossipSub 승인 기록 보유 시 → 추가 팝업 없이 즉시 방 키 전달
  - GossipSub 승인 기록 미수신 시 → 일반 승인 팝업 표시 (TTL 내 재승인 가능)
  - 핵심은 파일 전송이므로 재승인 팝업 1회 추가는 허용 가능한 UX 비용으로 간주
- 온라인 멤버 전원 전달 실패 시 → 피초대자에게 "연결 실패" 안내, TTL 내 재시도 가능

### 로그 기록

- 승인/거절 모두 로그에 기록 (결정한 멤버의 PeerId 포함)

## 새로운 사람 초대 (mDNS 탐색, 인트라넷 모드)

1. 채팅/파일 화면에서 `/invite` 실행
2. mDNS로 탐색된 로컬 피어 목록 표시
   - 닉네임#코드 형식으로 표시
   - 닉네임#코드 중복 시 IP 자동 표시
3. 목록에서 초대할 피어 선택
4. 직접 연결 → 상대방 승인 화면에 초대 알림 표시
5. 상대방 수락 → 방 키 전달 (Noise 암호화) → 입장 완료 + 친구 등록
- 초대 코드 생성/DHT 등록 불필요
- 다른 서브넷 피어는 목록에 미표시 → 친구 초대 경로 이용

## 기존 친구 초대

- 채팅/파일 화면에서 `/invite` → `[2] 친구 목록에서 초대` 경로로만 가능
- 친구 목록에서 선택 → 저장된 PeerId로 DHT 조회 → 직접 연결 → 초대
  - 인터넷 모드: 공개 DHT 조회
  - 인트라넷 모드: 로컬 피어들로 구성된 내부망 DHT 조회 (외부망 미사용, 동작 방식은 동일)
- 초대 코드 불필요
- DHT 조회 결과 오프라인 → "해당 친구가 현재 오프라인입니다." 안내 후 초대 취소

## 초대 수신 처리

### 방 미입장 상태 (메인 메뉴 등)

- 초대 알림 오버레이가 현재 화면 위에 표시
- 여러 초대가 대기 중인 경우 번호 목록으로 표시, ↑↓ 이동 후 Enter로 수락
- 수락 시 → 해당 방으로 바로 입장 (채팅/파일 화면으로 전환)
  - TTL이 남은 나머지 대기 초대는 자동 거절되지 않고 채팅/파일 화면 피드로 이전
  - 이후 방 입장 중 초대 수신 흐름과 동일하게 처리 (`[초대]` 피드 + `/accept <번호>`)
- 거절 시 → `D` 키로 해당 초대 거절, 알림에서 제거

### 방 입장 상태 (채팅/파일 화면)

- 초대 알림이 피드에 표시: `[초대] peer-a 가 dev.team 으로 초대했습니다 (/accept 1)`
- 여러 초대가 누적된 경우 각각 번호 부여
- `/accept` — 대기 중인 초대가 1건일 때 수락
- `/accept <번호>` — 여러 초대 중 특정 건 수락
- 수락 시 현재 방에서 자동 퇴장 후 초대받은 방으로 입장

### 공통

- TTL 내에 수락하지 않으면 초대 자동 만료
- 수락/거절 모두 로그에 기록

## 초대 권한

- 방에 있는 모든 멤버가 동등하게 초대 권한 보유
- 방장 개념 없음
