# 방 시스템

## 방 이름

- 도메인 스타일 형식: `dev.team`, `project-x.secret`, `lunch.chat`
- 형식: `이름.접미사` (최소 한 개의 `.` 필수)
- 허용 문자: 영문, 숫자, `-`, `.`
- 길이 제한: 3~32자

## 방 식별

- 내부적으로 랜덤 고유 ID 부여 (방 이름 중복 문제 해결)
- 사용자에게는 도메인 스타일 이름으로 표시
- DHT에는 고유 ID를 content ID로 하여 Provider Records로 등록
  - 방 생성 시 즉시 등록 (생성과 동시에 채팅/파일 화면 진입 → 온라인 상태로 간주)

## 방 수명

- 방 생성 시 수명 선택 (기본값: 1일)

| 옵션 | 설명 |
|------|------|
| 1일 | 기본값 |
| 3일 | - |
| 7일 | - |
| 무제한 | 수동 삭제 전까지 유지 |

- 수명 기준: 방 생성 시각으로부터 경과 시간
- 수명 정보는 rooms.enc에 저장 (생성 시각 + 수명 설정값)

### 수명 만료 체크

- 체크 주체: 클라이언트 로컬 (rooms.enc의 생성 시각 + 수명으로 계산)
- 체크 시점: 앱 실행 시 및 방 목록 화면 진입 시
- 만료된 방은 방 목록에 `만료됨` 표시, 입장 시도 시 "방이 존재하지 않습니다." 안내 후 목록 제거 유도
- 시스템 시계 조작으로 우회 가능하나, rooms.enc 자체가 계정 PW로 암호화되어 있어 추가 보안 위협 없음

## 방 접근

- 오직 초대 기반으로만 입장 가능
- 방에 있는 사람이면 누구나 초대 가능 (동등한 권한, 방장 없음)
- 한 번에 하나의 방만 접속 가능 (동시 다중 접속 불가)

## 방 재활성화

- 수명이 유효한 경우에만 재활성화 가능
- 모든 멤버가 방을 나가더라도 수명이 유효하면 언제든 재활성화 가능
  - rooms.enc에 저장된 방 정보(방 키, 내부 ID, 수명)로 복원
  - 첫 복귀 멤버가 DHT Provider Records에 자신을 등록
  - 이후 다른 멤버가 DHT 조회 → Provider 목록에서 온라인 피어 주소 수신 → 접속
  - 토렌트와 동일한 원리: 시더가 전부 나가도 누군가 돌아오면 공유 재개

## 재접속 인증

- 재접속 시 rooms.enc에서 방 키를 복호화하여 사용
- 방 키 보유 자체가 기존 멤버임을 증명 → 별도 승인 절차 불필요
- rooms.enc는 계정 PW → Argon2id → AES-256-GCM으로 암호화되어 있으므로
  로컬 파일 탈취만으로는 방 키 접근 불가

## DHT 레코드 유지

- 온라인 멤버가 주기적으로 Provider Records 재등록(republish)
- 모든 멤버 오프라인 → Provider Records 만료 → 재접속 시 첫 번째 멤버가 재등록
- Provider Records는 libp2p가 PeerId로 자동 서명 → 위조 등록 차단

## 오프라인 입장 시 파일 목록

- 온라인 피어 없이 입장 시 rooms.enc 캐시 기준으로 파일 목록 표시
- 상태바에 "마지막 동기화: N일 전" 표시 (오프라인 중 변경 사항이 있을 수 있음을 안내)
- 다른 피어 접속 시 BitfieldRequest → BitfieldResponse로 자동 동기화
- 동기화 후 rooms.enc 갱신 (추가/삭제된 파일 반영) + 상태바 안내 제거

## 방 퇴장 시

- 파일 시딩 일시정지 (다른 피어에게 청크 제공 중단)
- 로컬에 받은 파일은 삭제되지 않음
- 다른 피어가 시딩 중이면 파일 목록에 유지
- 재입장 시 로컬 파일 자동 시딩 재개

## 멤버 강퇴

- 강퇴 기능 없음 — 완전 탈중앙 P2P 구조의 의도적 설계
- 방 키를 가진 모든 멤버는 동등한 권한 보유, 중앙 권한 없음
- 원하지 않는 멤버가 있을 경우: 방을 나가고 새 방을 만드는 것이 올바른 대응
- 방 수명이 기본 1일로 짧아 실질적 피해 범위 제한됨

## 방 삭제

- 방 키 포함 모든 관련 데이터 삭제
- 로컬 다운로드 파일은 별도로 삭제 가능
