# 네트워크

## 프로토콜 스택

| 프로토콜 | 용도 |
|----------|------|
| GossipSub | 채팅 메시지, 파일 메타데이터 브로드캐스트 (StrictSign 모드) |
| request-response | 청크 1:1 전송, 초대 메시지 교환, Bitfield 교환 |
| mDNS | 같은 서브넷 피어 자동 발견 |
| Kademlia DHT | 피어 발견, 초대 코드 등록/조회, 방 Provider Records 등록 |
| relay | NAT 뒤의 피어 연결 중계 (relay 서버에 연결 당사자 IP 노출, 트래픽 내용은 Noise로 암호화) |
| DCUtR | NAT hole punching |
| identify | 피어 정보 교환 |
| Noise | 모든 libp2p 연결의 전송 구간 암호화 |

## 네트워크 모드

### 인터넷 모드 (기본값)

- 부트스트랩 피어 + Kademlia DHT + mDNS 전부 사용
- 어떤 네트워크에서든 DHT를 통해 피어 발견 가능
- 같은 LAN 피어는 mDNS로, 원격 피어는 DHT로 발견 → LAN + 인터넷 혼합 환경 자동 커버

### 인트라넷 모드

- 외부망과 물리적으로 완전 차단된 환경 (망분리, 에어갭)을 위한 모드
- 외부 부트스트랩 비활성화, 공개 DHT 미사용 → 내부망 외부로 데이터 유출 없음
- mDNS + 수동 피어 주소만 사용
- 같은 서브넷: mDNS로 자동 발견
- 다른 서브넷: 수동 피어 주소 목록에 등록하여 연결
- Kademlia DHT는 로컬 피어들로 구성된 내부망 DHT로 동작

#### 인트라넷 최초 세팅

로컬 DHT가 형성되려면 최소 1개의 피어와 먼저 연결이 필요:

1. 관리자(첫 번째 피어)가 자신의 `multiaddr` (IP:Port)를 내부 채널로 공유
2. 신규 참여자가 설정 → 수동 피어 주소 목록에 등록
3. 직접 연결 → 로컬 DHT 형성
4. 이후 초대 흐름은 로컬 DHT 또는 mDNS 탐색으로 정상 동작

#### 인트라넷 초대 흐름

인트라넷 모드에서는 **외부 DHT 기반 초대 코드가 완전 비활성화**되며, `/invite [1]`은 mDNS 탐색 목록 선택으로 대체:

1. `/invite` 실행 → mDNS로 탐색된 로컬 피어 목록 표시
2. 목록에서 초대할 피어 선택 (닉네임#코드 형식, 중복 시 IP 자동 표시)
3. 직접 연결 → 상대방 승인 → 방 키 전달 → 입장
4. 초대 코드 생성/DHT 등록 불필요

- 다른 서브넷 피어는 mDNS 탐색 불가 → 수동 피어 주소로 먼저 연결 후 친구 등록 → 이후 친구 초대 경로(로컬 DHT 조회)로 이용
- 친구 초대 시 PeerId 조회는 로컬 DHT를 사용 — 인터넷 모드와 동일한 흐름, 외부망 미접촉
- 메인 메뉴 `[3] 초대 코드로 입장` 항목도 인트라넷 모드에서는 비활성화

## DHT 레코드 무결성

DHT 용도별로 서로 다른 방식으로 무결성을 보장:

| 용도 | DHT 방식 | 무결성 |
|------|---------|--------|
| 방 멤버 등록 | Provider Records | libp2p가 PeerId로 자동 서명 — 위조 불가 |
| 초대 코드 등록 | 일반 DHT PUT + 생성자 서명 | `hash(코드)` 키 + 값에 Ed25519 서명 포함 — 키/값 모두 위조 불가 |

### Provider Records 방식 (방 멤버 등록)

- 방에 입장한 피어가 방 내부 ID를 content ID로 `provide` 호출
- libp2p가 자동으로 해당 피어의 Ed25519 키로 레코드 서명
- 조회 시 서명 자동 검증 → 위조된 주소 등록 원천 차단
- 악의적 피어가 provider로 등록을 시도해도 서명 검증 실패로 무시됨
- 설령 연결되더라도 방 키 없이는 승인 불가 → 실질적 위협 없음

### 일반 DHT PUT 방식 (초대 코드 등록)

- 등록 키: `hash(초대코드)` — 원문 비노출, 코드 없이 조회 불가
- 등록 값: `방 내부 ID + Ed25519 서명` (생성자의 개인키로 서명)
- 피초대자가 조회 후 생성자의 공개키(PeerId에서 파생)로 서명 검증
- 서명 검증 실패 시: 해당 응답 폐기, 다른 DHT 노드에서 재조회
- 악의적 DHT 노드가 값을 위조해도 서명 불일치로 탐지 → 입장 연결 시도 자체가 차단됨

## 피어 연결 제한

- 최대 동시 연결 피어 수 설정 가능 (단순 연결 수 제한)
- tit-for-tat 없음 — 모든 피어에게 동등하게 서비스

## 다른 네트워크에서 재접속

1. 방 목록에서 방 선택
2. 로컬 저장된 방 고유 ID로 DHT 조회
3. 현재 온라인인 피어 주소 수신
4. 자동 연결 → 방 입장
